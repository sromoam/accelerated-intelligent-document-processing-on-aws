Splitting and Section Classification Benchmarks

Section titled “Splitting and Section Classification Benchmarks”

Splitting finds where each document in a file starts and ends, and classification gives each of those sections a document class. Splitting and Section Classification explains how it works.

How to improve splitting and classification on your documents

Section titled “How to improve splitting and classification on your documents”

Your definitions. The classification model picks a document class by comparing each section with the description of every document class. Name the features that tell a class apart from its closest neighbor. For classes that still get confused, add a few-shot example. A small decision model is more sensitive to this wording than an LLM: give it one line per class about what the page looks like, such as “a typed formal letter with a salutation (Dear …) and a signature” (SC-12). See Improving accuracy.

Data quality. Long files, documents of the same class back to back, and pages that match no class are the hard cases. Poor scans hide the headers and page numbers the model uses to find where a document starts.

Questions

Section titled “Questions”
What the metrics mean
  • Page accuracy: the share of pages with the right document class.
  • Section accuracy: the share of true sections returned with exactly the right pages and the right document class.
  • Grouping score: how well the accelerator groups pages into documents, from 0 to 1, whatever their class. It is DocSplit’s packet score, which combines how pages are clustered and how they are ordered.
  • Boundary accuracy: the share of sections with exactly the right page range. The document class is not checked.
  • Label accuracy: of the sections with the right page range, the share with the right document class.

Full definitions: Document Split Classification Metrics in the evaluation guide, Telling a wrong boundary from a wrong label for boundary and label accuracy, and Stickler’s Document Packet Splitting Evaluation, which computes page accuracy, section accuracy and the grouping score.

Benchmark Datasets describes each dataset.

Does holistic classification beat page-by-page classification?

Section titled “Does holistic classification beat page-by-page classification?”

Bands show ±2 standard errors.

Answer: Holistic classification is a good place to start. With Claude Sonnet 5.5 it got 0.91 of sections exactly right, against 0.76 page by page, for $201 of classification per 1,000 packets; with Claude Haiku 5.5 reading text only it got 0.88 for $2.55 (SC-02). Test it on your own packets.

Can a decision model classify the sections?

Section titled “Can a decision model classify the sections?”

Bands show ±2 standard errors.

Answer: Not yet, with the preset’s class descriptions: Claude Haiku 5.5 classified 0.96 of sections right, against 0.81 to 0.83 for the Strands Decider 2B, whose classification cost slightly more ($19 to $20 against $17 per 1,000 packets). The decision model is more sensitive to how classes are described: a 100-packet re-run with one-line descriptions of what each page looks like is in progress, and in its first runs the Strands Decider 2B classified 0.90 of sections right with them. Test it on your own packets.

Details

Measured on each dataset’s preset, not the baseline setup.

Measured on release 0.6.15-develop-d1be93f, November 2026, us-east-1. Source: 15 Test Studio runs (6 failed documents left out of the scores), listed in benchmarks/results/guidance/SC-12.json.

The decision model is the Strands Decider 2B (StrandsAgents/strands-decider-2B-qwen3.5-v1-2610, 8-bit), on AWS Lambda, reading each section’s first page at 448 pixels; its cost is the function’s duration, with cold starts left out. These runs used the docsplit preset’s class descriptions, written for the LLM prompt.
