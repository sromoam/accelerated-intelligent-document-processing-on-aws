Confidence Assessment Benchmarks

Section titled “Confidence Assessment Benchmarks”

Confidence assessment gives every extracted value a score, so a person reviews the values most likely to be wrong instead of every value. Confidence Assessment explains how it works.

How to improve confidence on your documents

Section titled “How to improve confidence on your documents”

Your definitions. The scoring model reads each field’s description when it judges a value. Say what a right value looks like. Mark the fields you can’t do without as required: an empty required field goes to review even though it has no score. See Improving confidence.

Data quality. Poor scans cause more extraction mistakes, and catching those mistakes is the job confidence does. We measure it on ConfBench, which adds scan noise to real invoices.

Settings.

SettingWhat it changesQuestions
Scoring modeA separate scoring pass, scores inside the extraction call, or noneCF-03
Scoring modelThe model that scores each valueCF-02
Confidence thresholdThe score below which a value goes to reviewCF-01, CF-04
Page imagesWhether the scoring model sees the pagesCF-06

Questions

Section titled “Questions”
What the metrics mean
  • AUROC: the chance that a wrong value scores lower than a right one. 0.5 is a coin flip.
  • Calibration error: the gap between the scores and the measured accuracy.
  • Values below threshold: the share of values the threshold sends to review.
  • Errors below threshold: the share of wrong values the threshold sends to review.
  • ECARB at a 30% review budget: review the 30% of values with the lowest scores, and count how many times as many wrong values you find as a random 30% review would. 1× is no better than random, which the charts draw as a dashed line; the most possible is about 3.3×.
  • Errors caught reviewing 30% of values: the share of wrong values a reviewer finds by checking the 30% of values with the lowest scores. Checking 30% picked at random finds about 30%.

Full definitions: Stickler’s Confidence Metrics, which computes AUROC and calibration error.

Benchmark Datasets describes each dataset.

Which scoring model should I use?

Section titled “Which scoring model should I use?”

Bands show ±2 standard errors. Dashed lines mark coin flip (50%, no better than chance) and random review (1×, what reviewing a random 30% of values catches).

Answer: Claude Haiku 5.5 is a good place to start. On RealKIE invoices, reviewing the 30% of values it was least sure of found 2.4 times as many wrong values as reviewing a random 30% (this ratio is ECARB). That’s as many as Claude Sonnet 5.5, for a fifth of the cost. Amazon Nova Lite, the preset’s default, did worse than a random review (0.6 times). Test it on your own documents.

Details

Measured on release 0.6.15.dev1, November 2026, us-east-1. Source: 23 Test Studio runs, listed in benchmarks/results/guidance/CF-02.json.

Amazon Nova Lite, the preset’s scoring model, caught 18%, fewer than reviewing a random 30%. Amazon Nova 2 Lite caught 48%, fewer than Claude Haiku 5.5’s 71% at the same cost, and varied more between runs. W-2 forms aren’t shown: after Claude Haiku 5.5 extraction a run has about one wrong value, too few to compare scoring models.

Separate scoring pass or integrated into extraction?

Section titled “Separate scoring pass or integrated into extraction?”

Bands show ±2 standard errors. Cost axes differ by dataset.

Answer: If people review values by confidence, a separate scoring pass is a good place to start. If nobody does, turn confidence off: accuracy stayed the same and cost fell 13% to 28%. Test it on your own documents.

Details

Measured on release 0.6.15.dev1, November 2026, us-east-1. Source: 18 Test Studio runs, listed in benchmarks/results/guidance/CF-03.json.

Integrated scoring lowered W-2 accuracy from 1.00 to 0.96 to save $0.81 per 1,000 forms. On RealKIE invoices it ran as a separate pass anyway: the accelerator scores a document with line items in a separate pass even when integrated scoring is on.

Can a decision model score confidence?

Section titled “Can a decision model score confidence?”

Bands show ±2 standard errors. Dashed lines mark coin flip (50%, no better than chance) and random review (1×, what reviewing a random 30% of values catches).

Answer: Not yet; score confidence with an LLM, such as Claude Haiku 5.5. The Strands Decider 2B, reading page images, told right values from wrong ones less well (AUROC 0.68 against 0.80) and cost more than three times as much ($104 against $29 per 1,000 invoices). Reviewing its least-sure 30% of values found 2.0 times as many errors as a random review, against 2.5 times for Claude Haiku 5.5, too close to call. Claude Sonnet 5.5 found the most, 3.0 times, for $130. Test it on your own documents.

Details

Measured on release 0.6.15-develop-d1be93f, November 2026, us-east-1. Source: 12 Test Studio runs, listed in benchmarks/results/guidance/CF-08.json.

The decision model is the Strands Decider 2B (StrandsAgents/strands-decider-2B-qwen3.5-v1-2610, 8-bit), on an AWS Lambda function with 10 GB of memory; its cost is that function’s duration, with cold starts left out. It asks one yes/no question per extracted value against each page image of the section (up to 20 pages). Extraction ran on Claude Haiku 5.5 for every value. Reading OCR text instead of page images could not be measured on this release: the accelerator sent each section’s whole text in one request, longer than the 4,096 tokens the model reads, so half the invoices got no score (issue #2032). Its raw scores are not calibrated, so its calibration error depends on how often values are wrong and does not carry over to other documents.
